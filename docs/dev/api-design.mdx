## HMRC API Design

<br></br>

<center>The browser talks to same-origin Next.js route handlers. Those handlers add the HMRC access token and fraud-prevention headers, then call the HMRC sandbox APIs. The routes below describe the current implementation, not a public or stable external API.</center>

<br></br>

---

### OAuth routes

- `GET /api/hmrc/userRestrictedAuth/authorise` redirects the user to the HMRC sandbox authorisation page with the configured self-assessment read and write scopes.
- `GET /api/hmrc/userRestrictedAuth/callback` handles the authorisation response, exchanges the code for tokens, sets token cookies, and redirects to the account page.
- `GET /api/hmrc/userRestrictedAuth/refresh` exchanges a refresh token for new tokens.

Application sign-in uses a separate Auth0 integration; it is not the HMRC OAuth flow.

<br></br>

### Business and obligation routes

These are POST routes that receive request data from the app and call corresponding HMRC sandbox resources:

- `/api/hmrc/userRestrictedAuth/businessList`
- `/api/hmrc/userRestrictedAuth/businessDetails`
- `/api/hmrc/userRestrictedAuth/obligations/quarterly`
- `/api/hmrc/userRestrictedAuth/obligations/yearEnd`
- `/api/hmrc/userRestrictedAuth/quarterlyUpdateHistory`
- `/api/hmrc/userRestrictedAuth/listSelfAssessmentTaxCalculations`
- `/api/hmrc/userRestrictedAuth/retrieveSelfAssessmentTaxCalculation`
- `/api/hmrc/userRestrictedAuth/individualTaxCalculation`

The route handlers validate request JSON, NINOs, business IDs, tax years, and calculation identifiers before calling HMRC. Successful HMRC responses are checked against the required response fields for Business Details v2.0, Obligations v3.0, and Individual Calculations v9.0; malformed success responses produce a safe `502` response. HMRC error status codes are preserved, with error codes and messages returned after removing request identifiers and credentials. Server logs contain status, correlation ID, and error codes only, not upstream response bodies or customer data.
The quarterly update history route treats the documented Sandbox `MATCHING_RESOURCE_NOT_FOUND` summary/detail responses as no data and `NO_OBLIGATIONS_FOUND` as an empty obligations list. Other unsuccessful summary, obligations, or period-detail responses preserve HMRC's status and error details instead of returning partial history.
The calculation-list route calls the Sandbox Individual Calculations v9.0 endpoint `GET /individuals/calculations/{nino}/self-assessment/{taxYear}` with `Accept: application/vnd.hmrc.9.0+json`. HMRC's optional `calculationType` query filter is omitted when listing all calculations.
The API versions currently used by the HMRC routes, their Sandbox status, and the pre-release changelog review procedure are tracked in [`api-versions.md`](../../api-versions.md).

### Submission routes

- `POST /api/hmrc/userRestrictedAuth/submitQuarterlyUpdate` validates dates and tax-year-specific income/expense fields, then submits either a period update or a cumulative update according to the tax year. `taxTakenOffTradingIncome` is sent from tax year 2023–24 onward; earlier tax years omit it.
- `POST /api/hmrc/userRestrictedAuth/annualSubmission` accepts `action: "retrieve"` or `action: "submit"` for a self-employment annual summary.
- `POST /api/hmrc/userRestrictedAuth/individualTaxCalculation` triggers an HMRC Self Assessment calculation and returns its calculation ID. The quarterly page requests an in-year calculation; the year-end page requests an intent-to-finalise calculation. Neither action submits a final declaration.

These routes call HMRC's test API. The annual summary route does not implement a complete Self Assessment return or final declaration.

### Test and error behavior

- `POST /api/hmrc/applicationRestrictedAuth/createTestUser` requests an HMRC sandbox test user.
- `POST /api/hmrc/fraud/test` forwards fraud-prevention headers to HMRC's validation endpoint.
- HMRC errors are returned with an error message and, where available, the upstream status. Network failures are handled by the route, but response shapes are not yet a versioned public contract.

`app/api/hmrc/userRestrictedAuth/helper.ts` is shared route code, not an endpoint: only files named `route.ts` expose App Router routes.
