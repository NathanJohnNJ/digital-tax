## Fraud Prevention Headers

<br></br>

<center>HMRC fraud-prevention headers are assembled for outbound requests by `buildFraudPreventionHeaders`. Browser-derived values are collected separately and passed to the server with the app's request.</center>

<br></br>

---

### Client headers

`client/fraud/clientData.ts` currently builds values for:

- `Gov-Client-Connection-Method`
- `Gov-Client-Browser-JS-User-Agent`
- `Gov-Client-Device-ID`
- `Gov-Client-Multi-Factor`
- `Gov-Client-Public-IP` and `Gov-Client-Public-IP-Timestamp`
- `Gov-Client-Public-Port`
- `Gov-Client-Screens`
- `Gov-Client-Timezone`
- `Gov-Client-User-IDs`
- `Gov-Client-Window-Size`

The browser helper obtains screen, window, timezone, and user-agent details and stores a device ID in local storage. The server derives the client public IP from the trusted incoming request; it does not trust a client-submitted IP value. Some browser values can be empty or unavailable, so the generated header names alone do not prove that the values meet HMRC's current requirements.

<br></br>

---

### Vendor headers

The server helper resolves `Gov-Client-Public-IP` from the trusted Vercel request IP using the same resolver shown in the IP diagnostics, and resolves `Gov-Vendor-Public-IP` from the server-side IP lookup (falling back only to a configured, valid server IP). If either address cannot be resolved, it fails the HMRC request instead of sending an empty IP header.

The server helper adds:

- `Gov-Vendor-Forwarded`, built from the client IP and configured proxy/server IPs.
- `Gov-Vendor-License-IDs`, built from the configured application name and licence key.
- `Gov-Vendor-Product-Name` and `Gov-Vendor-Version`, built from the configured application name.
- `Gov-Vendor-Public-IP`, looked up by the server through an external IP service.

Set and verify the related environment variables and proxy chain for the deployment. The server uses the first `x-forwarded-for` address only when running behind Vercel's trusted ingress, and validates it as an IP address; if it is invalid, the validated Vercel `x-real-ip` value is used as a fallback. Outside Vercel, client IP headers are not trusted. Do not infer the true network path from defaults or development values.

<br></br>

---

### Validation and safeguards

`POST /api/hmrc/fraud/test` sends the generated headers to HMRC Sandbox's `GET /test/fraud-prevention-headers/validate` endpoint. It validates the fraud-prevention headers attached to that same request. Use its feedback during integration, but treat it as a test of the submitted request, not a general compliance certification.

Before production, review the current HMRC fraud-prevention specification and each data source. In particular, replace the fixed user ID currently present in the browser helper with an appropriate per-user value, review IP collection and proxy trust, and ensure the required client information is collected accurately and transparently. Do not log or expose access tokens or unnecessary personal data.
